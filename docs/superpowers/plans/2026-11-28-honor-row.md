# Honor Row and Click to Open Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional honor row on the XP / Reputation bar, and clicks on the reputation / honor rows that open Blizzard's reputation / PvP pane.

**Architecture:** Pure rules in `Core/Tracking.lua` (honor row data, its text, which row a click hit), the client side in `Bars/Tracking.lua` (a third row in the existing layout, a `showHonor` option, honor events, an `OnMouseUp` handler). No new files.

**Tech Stack:** Lua 5.1, plain-Lua tests (`lua tests/run.lua`), luacheck.

**Spec:** `docs/superpowers/specs/2026-11-28-honor-row-design.md` (approved 2026-11-28); look: `docs/mockups/6-honor.html`, `docs/mockups/APPROVED.md` section 6.

## Global Constraints

- Lua 5.1 code (no `goto`, `//`, `table.unpack`); tests and `luacheck AnotherHUD` (0 warnings) pass after each task.
- Secret values: no arithmetic, comparisons or `tostring` on client numbers unless `plain()`; only `== nil` checks on raw values; secrets go only to `SetMinMaxValues` / `SetValue`.
- Honor color (1, 0.24, 0) as `Theme.trackingColors.honor`.
- Text "Honor level %d  %s / %s (%d%%)": the "Honor level" part through `ns.L`, German in `Locales/deDE.lua`; percent `floor(value * 100 / max)`, left out when max <= 0.
- Option `showHonor = false` (default off); checkbox label "Show honor", tooltip "Show your honor and honor level.".
- Row order XP, reputation, honor; rows off or empty are skipped and the bar reflows.
- Clicks: left button, mouse up; reputation row -> `ToggleCharacter("ReputationFrame")`, honor row -> `TogglePVPUI()`, XP row nothing; only when the function exists, `InCombatLockdown()` is false and Edit Mode is closed.
- Every new client API / event gets an `UNVERIFIED (check in client)` comment and a CHECKLIST line.
- Lua edited with the Write / Edit tools.

## Review Focus

1. Three rows: a divider between every two neighbouring rows (today the code draws exactly one divider, only for two rows), sharp in every skin.
2. Honor with a secret value or max: the row fills, no text, no error.
3. A click in combat or in Edit Mode: nothing happens, no error.
4. A click on the honor row while reputation is off: the honor row (now second) is still the one that opens the PvP pane (the hit test maps to the rows shown, not fixed slots).
5. `UnitHonor` missing (old client): no honor row, no error, even with Show honor on.
